## 缘起

我写这个，是因为手边那些扫描器一个比一个重。装半天依赖，跑一圈吐出几十页报告，点开一看一半是误报，剩下的一半还得自己重放一遍才敢信。可平时做自查，我想要的其实很简单：给个 URL，看一眼，告诉我这个值不值得继续往下挖。

所以有了这个脚本。名字取自百眼巨人的幼体——先睁一只眼，只做基础验证，不负责全视，也不搞花里胡哨。几百行代码，两个依赖，跑完就走。

## 它干嘛的

给一个 URL，它把首页和首页直接链接里的参数捞出来：URL query、表单 GET / POST、隐藏字段、链接里的 query，去重、按来源排好序，然后挨个试三样——布尔盲注、反射标记、基础路径遍历。参数最多 6 个，默认请求上限 120，间隔 0.8 秒，我不想把人家日志刷爆。

不是全家桶。没有爬虫，没有端口扫描，没有指纹库，没有报告生成器，没有利用链。它的活儿只有一件：验证。

三类判定我卡得很死：

- **布尔盲注验证**：同一个参数发两个恒真、两个恒假。恒真都得跟基线长得一样，恒假都得明显偏离，两组内部还得各自自洽。比对前把数字和空白抹掉，不然带时间戳的页面会一直给你报洞。WAF 拦截页最爱伪造这种差异，四请求这么卡一道能少挨不少骂。代价是漏报，我认。
- **反射标记验证**：只发 `">argulus_xxxxxx<` 这种无害标记，不发 `<script>`。只认 `Content-Type` 含 html 且原样未转义回显；被 `&lt;` 吃掉的一律不算，JSON 里回显个字符串也不算。
- **路径遍历验证**：只认 `/etc/passwd` 和 `win.ini` 的特征。发 payload 前先打一个肯定不存在的文件名当噪声基线，404 页里碰巧带 `root:` 的用这条直接排掉。带 `%2f` 的 query 是手工拼的，交给 urlencode 会变成 `%252f`，payload 直接废掉。

只分析首页和首页直接链接，不爬深；POST 只测表单自己写的 action，不猜路径。这些限制是我故意留的，别来提 issue 让我加爬虫。

## 装

Python 3.8+。

```
pip install -r requirements.txt
```

就 requests 和 rich 两个。要开那个局域网资产自查的小窗口（表格、CSV/JSON 导出、进度条都在里面），再加一句：

```
pip install -r requirements-gui.txt
python neteyes.py
```

## 跑

基础扫描，参数让脚本自己分析：

```
python scan.py -u http://127.0.0.1:8000/?id=1
```

只测我指定的两个参数：

```
python scan.py -u http://127.0.0.1:8000/?id=1 -p id,page
```

慢一点，超时放宽：

```
python scan.py -u http://127.0.0.1:8000/?id=1 -d 1.0 -t 8
```

把结构化结论写成 JSON：

```
python scan.py -u http://127.0.0.1:8000/?id=1 --report out.json
```

不带任何参数直接 `python scan.py`，进交互界面：实心块字 logo，目标只问一次，直接回车全走默认，输入 `a` 才展开参数、参数上限、延迟、请求上限、报告这些高级项。

几个我常调的开关：`--max-params` 参数上限（默认 6）、`--max-requests` 请求上限（默认 120，按参数均分，不让第一个参数吃光）、`--report` 输出 JSON。`-d` 下限 0.2 秒，`-t` 下限 1 秒，别调成 0。域名和公网 IP 默认直接拦掉，真有书面授权才加 `--authorized`——加之前先确认那张纸在你手上。URL 里带 `&` 时整个 URL 用双引号包住，CMD 会把它当命令分隔符。

本地怎么起靶场、预期输出长什么样、常见报错怎么排查，见 [docs/TESTING.md](docs/TESTING.md)。

## 准确率与复核

先把话说明白：**没弹框，绝不等于目标安全。**

这工具偏向"宁可漏报，绝不误报"。没有报错注入，没有时间盲注，没有 DOM 型，没有编码绕过的遍历；二次注入、要登录态的点、复杂 POST 场景，一个都不测。它漏得挺多，我认。

脚本给的置信度（高 / 中 / 低）只是代码自评，不是结论。JSON 里 `verified` 恒为 false、`reviewer` 恒为 null，结论表里"真实性"一律写着 `待人工复核`——我不让工具自己给自己打勾，也不写什么"准确率 XX%"这种数字。

**所有报出来的洞，必须真人手工复核一遍**：自己重放 payload、看原始响应、确认不是 WAF 拦截页或缓存搞的鬼，再决定要不要写进报告。别拿终端输出当结论，也别拿它去交差。
